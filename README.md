# ممرّ — Mamarr

موقع ثابت ثنائي اللغة (عربي/إنجليزي) للوجستيات وسلاسل الإمداد في الخليج، مبني بـ [Eleventy](https://www.11ty.dev/).
لا قاعدة بيانات، لا خادم، لا تكلفة استضافة تقريبًا. تكتب المقالات بصيغة Markdown، وتحدّث الأسعار في ملف JSON واحد.

## التشغيل محليًا

```bash
npm install
npm run serve      # معاينة حيّة على http://localhost:8080
npm run build      # يُخرج الموقع الجاهز في مجلد _site/
```

## هيكل المشروع

```
src/
├── _data/
│   ├── site.json        إعدادات الموقع: الاسم، النطاق، رابط النشرة، البريد، لينكدإن
│   ├── i18n.json        كل نصوص الواجهة بالعربية والإنجليزية
│   └── rates.json       جدول أسعار الشحن (يُحدَّث أسبوعيًا)
├── _includes/           القوالب (base, article) والأجزاء المشتركة
├── ar/                  الصفحات العربية
│   ├── articles/        المقالات  ← أضف ملف .md هنا
│   └── ports/           صفحات الموانئ
├── en/                  الصفحات الإنجليزية (نفس البنية)
├── css/style.css
└── index.html           يحوّل الزائر إلى /ar/ أو /en/ حسب لغة متصفحه
```

## كيف تضيف مقالًا

1. أنشئ ملفًا في `src/ar/articles/اسم-قصير-بالانجليزي.md` بهذا الرأس:

```markdown
---
title: عنوان المقال
dek: سطر أو سطران يلخّصان المقال (يظهر في القوائم وتحت العنوان)
description: وصف لمحركات البحث (١٥٠ حرفًا تقريبًا)
date: 2026-11-15
key: same-slug
---

نص المقال بصيغة Markdown…
```

2. للنسخة الإنجليزية أنشئ ملفًا **بنفس الاسم** في `src/en/articles/`. زر تبديل اللغة يعتمد على تطابق المسار.
3. `npm run build` — المقال يظهر تلقائيًا في الصفحة الرئيسية وصفحة التحليلات مع التاريخ ومدة القراءة.

تنسيقات مدعومة داخل المقال: عناوين `##`، قوائم، جداول، اقتباس `>` (يظهر كبارز برتقالي)، و`**غامق**`.

## أسعار الشحن — قسمان مختلفان

ملف `src/_data/rates.json` فيه قسمان، ولكلٍّ طريقة تحديث مختلفة تمامًا:

| القسم | المحتوى | من يحدّثه |
|---|---|---|
| `indices` | المؤشرات العالمية: WCI, SCFI, BDI | **آليًا** كل جمعة عبر GitHub Action |
| `lanes` | أسعار الخطوط الخليجية | **أنت يدويًا** — وهي ما يميّز ممرّ |

### تشغيل التحديث الآلي (مرة واحدة)

1. سجّل في [oilpriceapi.com](https://www.oilpriceapi.com) واحصل على مفتاح مجاني (٥٠ طلبًا يوميًا — تحتاج ٣ فقط أسبوعيًا).
2. في GitHub: **Settings → Secrets and variables → Actions → New repository secret**
   - الاسم: `OILPRICEAPI_KEY` — القيمة: مفتاحك.
3. من تبويب **Actions** شغّل "تحديث مؤشرات الشحن" يدويًا أول مرة للتأكد.
4. في `rates.json` غيّر `"indices_sample": true` إلى `false` ليختفي شريط "قيم توضيحية".

بعدها يعمل كل جمعة ١:٠٠ ظهرًا بتوقيت عُمان: يجلب المؤشرات، يحدّث الملف، يتأكد أن الموقع يُبنى، ثم يدفع التغيير — وNetlify ينشره تلقائيًا.

بدون المفتاح لا يفشل شيء: السكربت يخرج بهدوء والموقع يبقى يعمل بالقيم الموجودة.

للتشغيل محليًا: `OILPRICEAPI_KEY=xxxx node scripts/update-rates.mjs`

### تحديث أسعار الخطوط (كل أسبوع، يدويًا)

افتح `src/_data/rates.json` → قسم `lanes`:

- غيّر `updated` إلى تاريخ اليوم.
- لكل خط: أضف السعر الجديد إلى **نهاية** `series` واحذف الأقدم (احتفظ بـ٨ قيم)، واجعل `usd` مساويًا لآخر قيمة، و`change_pct` نسبة التغير عن الأسبوع السابق.
- عند أول بيانات حقيقية غيّر `"sample": true` إلى `false` — يختفي شريط "قيم توضيحية".
- لإضافة خط: انسخ أي عنصر في `lanes` وغيّر `id` والأسماء. **مهم:** `slug` في `from` و`to` و`via` يجب أن يطابق ميناءً موجودًا في `ports.json` وإلا انكسر الرابط.
- `days` = زمن العبور التقريبي بالأيام. `via` = ميناء إعادة الشحن؛ احذف الحقل كله إن كانت الخدمة مباشرة.
- جدول الأسعار يفلتر بالوجهة ويبحث بالمصدر ويرتّب بالسعر والسرعة والتغير، وملخّصه (الوسيط وأكبر ارتفاع وانخفاض) يُحسب آليًا من المعروض — لا شيء منه يحتاج تحديثًا يدويًا.

## الربط الداخلي والبيانات المنظمة

- **ربط المصطلحات تلقائيًا**: أول ذكر لكل مصطلح من `glossary.json` داخل نص المقال يصير رابطًا لصفحته، بحد أقصى ١٠ روابط لكل مقال. يتجاهل العناوين والروابط الموجودة والأكواد، فلا يفسد النص. المنطق في فلتر `linkTerms` داخل `.eleventy.js`.
- **اقرأ أيضًا**: يُحسب آليًا من المصطلحات والموانئ المذكورة في النص. صفحات الموانئ تعرض خطوط الشحن المارة بها من `rates.json`.
- **بيانات منظمة (JSON-LD)**: تُحقن في كل صفحة من `src/_includes/schema.njk` — Article للمقالات، Event لكل معرض، DefinedTerm للمصطلحات، Place للموانئ، مع Organization وPerson وBreadcrumbList في كل صفحة. تحقق منها بعد النشر عبر Google Rich Results Test.
- **البحث**: `/{lang}/search/` يقرأ `search.json` المولّد آليًا من كل المحتوى. لا يحتاج صيانة — كل ما تضيفه يدخل الفهرس تلقائيًا.
- **صفحة ٤٠٤**: `/404.html`، وNetlify يستخدمها تلقائيًا.

## الأدوات والصفحات الإضافية

- **حاسبة التكلفة الواصلة** `/ar/calculator/` و`/en/calculator/` — معاملات الدول في `src/_data/gcc.json` (نسبة الرسم، ضريبة القيمة المضافة، سعر الصرف). راجعها سنويًا أو عند أي تغيير ضريبي.
- **المعارض والمؤتمرات** `/ar/events/` — كل الأحداث في `src/_data/events.json`. التصنيف إلى (جارية/قادمة/ما مضى) يحدث في متصفح الزائر حسب تاريخ اليوم، فالصفحة تبقى دقيقة بلا إعادة بناء. راجع القائمة كل ربع سنة وحدّث حقل `verified`. استخدم `conflict: true` حين تتضارب المصادر، و`tbd: true` لحدث سنوي لم تُعلن تواريخه.
- **الموانئ** `/ar/ports/` — كل الموانئ في `src/_data/ports.json` مصنّفة بالمنطقة. الميناء العادي تُولَّد صفحته آليًا من الملف. الميناء الذي يستحق صفحة تفصيلية: أضف `"detailed": true` في الملف، وأنشئ `src/ar/ports/<slug>.md` و`src/en/ports/<slug>.md` — عندها يتوقف التوليد الآلي ويُستخدم ملفك. لإضافة منطقة جديدة أضفها إلى `regions` أولًا.
- **الأيام المجانية ورسوم التأخير** `/ar/freetime/` و`/en/freetime/` — كل البيانات في `src/_data/freetime.json`. لكل ميناء سجلّ فيه **ساعتان منفصلتان**: `carrier` (demurrage و detention، يحددها الخط البحري) و`terminal` (port storage، تحددها المحطة). اترك `terminal: null` حين لا توجد تعريفة محطة منشورة — الصفحة تعرض دعوة للمساهمة مكانها بدل رقم مخترع.
  - كل رقم يحتاج `source` (رابط التعريفة المنشورة) و`sourceName` و`verified` (تاريخ مراجعتك له). **لا تضف رقمًا بلا مصدر.**
  - حقل `scope` مهم: تعريفات الناقلين في الخليج قُطرية لا تخص ميناءً بعينه، وقول ذلك صراحةً أصدق من إيهام القارئ بأن الرقم خاص بصحار وحده.
  - السجلّ يظهر تلقائيًا في صفحة الميناء نفسها (المولّدة والتفصيلية معًا) عبر `freetime-port.njk`، ولا يحتاج أي تعديل في صفحة الميناء.
  - **راجعها كل ربع سنة**، وبعد أي اضطراب كبير في الملاحة — إشعارات الناقلين تغيّر هذه الأرقام مؤقتًا. حدّث `verified` في كل مراجعة حتى لو لم يتغير الرقم.
  - الفلاتر والمناطق غير موجودة هنا عمدًا: ستة سجلات لا تحتاج فلترًا. أضف فلتر منطقة حين تتجاوز خمسة عشر ميناءً.
- **إشعارات الناقلين** `/ar/advisories/` و`/en/advisories/` — كل البيانات في `src/_data/advisories.json`.
  - الأصل الحقيقي لهذه الصفحة هو `changelog`: سجل مؤرَّخ لما تغيّر، أحدثه أولًا. **لا تحذف سطرًا قديمًا أبدًا** — التسلسل هو ما لا يملكه غيرنا، والجدول وحده يملكه أي أحد. لكل سطر `text` (النص الكامل في الصفحة) و`short` (سطر قصير يظهر في الواجهة الأولى).
  - `dropoff` و`pickup`: القيمة `0` تعني مجانًا، وأي رقم آخر بالدولار لكل حاوية. `effective` اختياري ويظهر تحت اسم الموقع.
  - الصفحة تقول صراحةً إن المصدر **ناقل واحد**. حين تصل مساهمات من ناقلين آخرين، أضف حقل `carrier` لكل سجل وحوّل `carrier` العلوي إلى قائمة — ولا تخلط ناقلين في جدول واحد بلا تمييز.
  - **راجعها كل أسبوعين**، وفورًا بعد أي حدث ملاحي كبير. حدّث `asOf` في كل مراجعة حتى لو لم يتغير رقم.
  - أحدث سطرين يظهران تلقائيًا في لوحة الواجهة الأولى، و«منذ كم يومًا» يُحسب في المتصفح لا في البناء — فالصفحة لا تكذب على القارئ إن لم تُبنَ منذ أسبوع.
### خريطة الواجهة

الخريطة في الصفحة الأولى ليست صورة ولا مكتبة خرائط: كل شيء فيها SVG مولّد وقت البناء من بياناتنا.

- **الإطار مُجمَّد** في `src/_data/mapframe.json`. لو اشتُقَّ من الموانئ لأعاد ميناءٌ جديد ترتيب الخريطة كلها. تغييره يوجب إعادة توليد الساحل، وإلا انزاح البرّ عن النقاط.
- **الساحل** في `coastline.json` من Natural Earth (ملك عام، بلا شرط نسبة)، مقصوص على الإطار ومبسّط بـ Douglas–Peucker. يُعاد توليده بـ `node scripts/build-coastline.mjs` — مرة واحدة باليد، فالسواحل لا تتحرّك.
- **مواضع الموانئ** محسوبة من `ports.json` في فلتر `regionMap`، بإسقاط مستطيل مصحَّح بجيب تمام خط العرض. لا نقطة مرسومة باليد.
- **السلاسل تلزم حوضًا واحدًا** حتى لا يعبر خطٌّ يابسة. لهذا انقسم الخليج عند قطر: ميناء حمد على الساحل الشرقي لشبه الجزيرة، ووصله بالبحرين يقطعها. والفجوة بين جبل علي وخورفكان هي مضيق هرمز، تُرسم قوسًا منقّطًا يدور حول رأس مسندم. **إن أضفت ميناءً إلى سلسلة، تحقّق بصريًا أن الخطّ لم يعبر برًّا** — التعليق تحت الخريطة يَعِد بذلك.
- **بطاقات الأسماء مضبوطة يدويًا** في `region-map.njk`: الموانئ المتجاورة تتزاحم. على الشاشات الصغيرة تُختصر إلى الموانئ العُمانية وجبل علي، لأن اللوحة تنكمش إلى أقل من نصف عرضها فتصير وحدة الخط نصف حجمها.
- **كل لون في الخريطة مكتوب في الوسم نفسه، لا في CSS.** هذه ليست مسألة ذوق: متصفّح لا يطبّق `fill` من الأنماط على SVG يُسقط كل عنصر إلى قيمته الافتراضية — والافتراضي أسود — فتصير الخريطة مستطيلًا أسود تامًّا. حدث ذلك فعلًا على متصفّح مستخدم بينما كانت تعمل عندي. لوحة الألوان في أعلى `region-map.njk` تحت `C`، والأنماط للحركة والتفاعل فقط.
- **اختبرها بلا أنماط قبل أي تغيير فيها.** افتح القسم في صفحة بلا `style.css` إطلاقًا: إن ظهرت الخريطة كاملة الألوان فهي سليمة، وإن ظهر أي سواد فقد تسرّب لون إلى CSS.
- ولنفس السبب لا تستعمل `color-mix()` هنا: المتصفّح الذي لا يدعمها يُسقط التصريح كله.
- **اللوحة التفاعلية** تقرأ كل شيء من `data-*` على عقدة الميناء: الرمز والبلد والأيام المجانية وأقرب ثلاثة موانئ برًّا من `distances.json`. إحداثيات الخطوط تُؤخذ من `map.byId` لا من عقد جدول المسافات — تلك تحمل إحداثيات جغرافية لا إحداثيات اللوحة، ووصلها مباشرة يرسم خطًّا إلى الزاوية (٠،٠).
- **الحركة زينة فقط.** الخريطة مقروءة تمامًا وهي ساكنة، ومع `prefers-reduced-motion` تُخفى النبضات والهالات بدل أن تتجمّد شُرَطًا بلا معنى.

### أين يعيش الموقع

- **عنوان النشر الحالي:** <https://zingy-truffle-cffeb4.netlify.app> — مسجّل في `site.json` تحت `deployUrl`.
- **النطاق المقصود:** `mamarr.com` في `site.json` تحت `url`، ولم يُشترَ بعد. حين تشتريه وتربطه بنيتليفاي، احذف `deployUrl`.
- لا تخمّن العنوان: نيتليفاي يعطي اسمًا عشوائيًا، ولا يسجّله في المستودع ولا في GitHub. هذا السطر هو المكان الوحيد الذي يحفظه.

### المسافات البرية — تُبنى مرة ولا تُصان

`src/_data/distances.json` يحمل مسافة القيادة وزمنها بين الموانئ الموصولة بشبكة طرق واحدة: الخليج والعراق والأردن واليمن. المصدر بيانات OpenStreetMap عبر محرّك OSRM.

- **لا جدول زمني لهذه المهمة.** الطرق لا تتحرّك، فالمهمة `build-distances` يدوية فقط من تبويب Actions. شغّلها إن أضفت ميناءً بريًا أو صحّحت إحداثية، لا غير ذلك.
- **لا تحرّر الأرقام بيدك.** الملف كله مُولَّد. الزوج الذي لا يُرجع له المحرّك طريقًا يسقط من الجدول ولا يُكتب له رقم مخمّن — نفس قاعدة الخطوط غير المعايَرة.
- **إيران ومصر مستثناتان عن قصد.** الطريق إليهما موجود هندسيًا وليس طريق شحن فعليًا من موانئنا، وإدراجه يعطي رقمًا صحيحًا حسابيًا ومضلّلًا عمليًا. إن أردتهما، عدّل `LAND_CONNECTED` في السكربت.
- **الزمن زمن قيادة صافٍ** ولا يشمل المنفذ الحدودي. هذا مكتوب على الصفحة نفسها لا هنا فقط، لأن من يقرأ الرقم قد يبني عليه وعدًا لعميل.
- **صحار وصلالة وجبل علي** لا تنشر لها قائمة UN/LOCODE إحداثيات، فهي مكتوبة في `ports.json` بحقل `coordsSource` يسمّي مصدرها، ومعلنة على الصفحة، ودقّتها على مستوى الموقع لا بوابة الميناء. إن كان لديك إحداثية بوابة أدقّ فعدّلها هناك وأعد تشغيل المهمة.
- **لا تُضف خدمة بحث جغرافي إلى هذا السكربت.** جرّبتُ Nominatim فسقط التشغيل: حجبت الطلب برمز 503، ولم تجد «صحار» و«صلالة» أصلًا. البناء الدائم لا يُعلَّق على خدمة متقلّبة تحجب عناوين الخوادم؛ الإحداثيات تعيش في المستودع حيث تُراجَع وتُصحَّح.
- **اليمن مستثنى** من جدول المسافات: الشحن البري إليه من الخليج ليس خطًّا قائمًا. عدن تبقى في `ports.json` كميناء، لكنها خارج المصفوفة.
- النسبة المطلوبة لبيانات OSM مكتوبة في الملف وتظهر أسفل الجدول: ODbL.

### مِجسّ تغطية AIS — قياس لا ميزة

مهمة `ais-probe` ليست ميزة في الموقع. هي قياس: تتصل بالبثّ المجاني من aisstream.io تسعين ثانية، وتعدّ كم سفينة ترى فعلًا حول موانئنا، وتكتب تقريرًا في ملخّص التشغيل. **لا تكتب في المستودع شيئًا ولا يظهر رقمها على الموقع.**

- تحتاج سِرًّا باسم `AISSTREAM_KEY` — مفتاح مجاني من aisstream.io. بلا المفتاح تفشل المهمة برسالة واضحة.
- سبب وجودها: البثّ المجاني **أرضي** لا قمري، فهو ضعيف في عرض البحر وقويّ قرب الساحل. موضوع ممرّ هو الساحل، فالقياس يحسم ما إذا كانت التغطية تكفي.
- **الترخيص: محسوم ومفتوح.** الخدمة تنشر بياناتها تحت **CC BY 4.0**، وصفحتها تجيب صراحةً: إعادة النشر مسموحة مع نسبة aisstream.io وإبقاء إشعار الترخيص، والاستخدام التجاري مسموح. هذا أول مصدر بيانات حيّة نجده يسمح بالنشر دون استئذان — فلا رسالة ولا انتظار إذن.
- قيود تشغيلية تُبنى داخلها: ثلاثة اتصالات لكل مفتاح، حتى خمسين صندوقًا في الاشتراك، ورسالة الاشتراك خلال ثلاث ثوانٍ من الاتصال وإلا قُطع، ولا ضمان لوتيرة التحديث.
- **ترتيب أركان الصندوق يقتل بصمت:** الخدمة تتوقّع خطّ العرض الأعلى أولًا (الركن الشمالي الغربي ثم الجنوبي الشرقي). الصندوق المقلوب يُقبل بلا خطأ ويُعيد صفرًا، فيبدو كأنه انعدام تغطية. كلّفني ذلك تشغيلًا كاملًا.
- AISHub مرفوض لسببين: يشترط أن تُشغّل مستقبِلًا بنفسك، ويمنع تمرير البيانات الخام إلى الآخرين بمقابل أو بغيره. أي أن نشرها على ممرّ ممنوع حتى لو ركّبت الجهاز.

### رموز UN/LOCODE — المعرّف المعياري للموانئ

لكل ميناء في `ports.json` حقل `locode` (مثل `OMSOH` لصحار) وبعضها `coords`. المصدر: قائمة UNECE الرسمية.

- **لا تخمّن رمزًا.** ابحث عنه في [قائمة UNECE](https://unece.org/trade/cefact/UNLOCODE-Download) أو في [مفردات UN/CEFACT](https://vocabulary.uncefact.org/unlocode). المطابقة الآلية بالاسم تُخطئ: رمز المطار كثيرًا ما يشبه رمز الميناء (CNSHA مطار شنغهاي، CNSGH ميناؤها)، فتحقّق من حقل Function — الرقم `1` يعني ميناءً بحريًا.
- `coords` موجود فقط حين تنشره القائمة (٤٢ من ٥٦). **لم تُخترع إحداثية واحدة**، والميناء بلا إحداثيات لا يحمل الحقل أصلًا.
- الرمز يظهر في صفحة الميناء وقائمة الموانئ، و**يُبحث به**: كتابة `OMSOH` في بحث الموقع أو في فلتر قائمة الموانئ تصل إلى صحار. هذا ما يكتبه المحترف.
- حالات حسمتها بالمصدر لا بالذاكرة، وتستحق مراجعتك إن اختلفت معها: ميناء السلطان قابوس `OMSTQ` (لا `OMOPQ`، فحالتها غير مؤكدة في القائمة)، لاغوس `NGLOS` (لا `NGAPP` وهي رصيف أبابا وحده)، تانجونغ بريوك `IDJKT` (لأن `IDTPP` مصنّفة محطة برية لا ميناءً).

### كيف تعمل تقديرات أسعار الخطوط — اقرأ هذا قبل لمس `rates.json`

التقدير **محسوب وقت البناء، وليس مخزّنًا**. لا يوجد حقل `usd` في أي خط، وهذا متعمد.

```
التقدير = آخر قيمة للمؤشر × calibration.ratio
```

- `calibration: null` يعني **لم يُعاير** — الصفحة تعرض خانة فارغة ودعوة لإرسال عرض. **لا تملأها برقم تقديري أبدًا.** الجدول الصادق الناقص أفضل من الكامل المخترع، وهذه ليست مسألة ذوق: القارئ لا يستطيع تمييز رقمك المخترع من رقم حقيقي، فيبني عليه قرارًا.
- لمعايرة خط وصلك عرض سعر له: `ratio = السعر ÷ قيمة المؤشر في أسبوع ذلك العرض`. سجّل `quotes` (عدد العروض خلف النسبة) و`calibrated` (تاريخ اليوم) و`index` (افتراضيًا `wci`).
- وصل عرض ثانٍ لنفس الخط؟ احسب متوسط النسب، وزد `quotes`، وحدّث `calibrated`.
- **الثقة تُعرض ولا تُخفى**: الفلتر يحسب عمر المعايرة ويضع `conf-fresh` (حتى ٩٠ يومًا) أو `conf-aging` (حتى ١٨٠) أو `conf-stale`، والرقم يبهت كلما قدُم. تاريخ المعايرة وعدد العروض ظاهران تحت كل رقم.
- المزامنة الأسبوعية تأتي مجانًا: مهمة المؤشرات تدفع قيمة جديدة، ونتليفاي يعيد البناء، فتتحرك كل التقديرات معها. **لا توجد مهمة ثانية تصونها.**
- المنهجية منشورة للقارئ في `/ar/method/` و`/en/method/`. إن غيّرت الحساب، غيّر تلك الصفحة في نفس الالتزام.

### لماذا لا تُشترى أسعار الخطوط

قرار مقصود، لا نقص. واجهات أسعار الخطوط التجارية مرخّصة للاستعمال الداخلي لا للنشر — نص شروط إحداها حرفيًا: «لا يُسمح بإعادة التوزيع أو البيع أو النشر دون موافقة خطية مسبقة». وFreightos تحتفظ بكل الحقوق غير الممنوحة صراحةً.

فالموقع يقف على طبقتين فقط، وكلتاهما قابلة للنشر:

1. **مؤشرات منشورة بإسناد** — WCI وSCFI وBDI تعمل الآن. أضفت FBX وXSI إلى `scripts/update-rates.mjs` برموز **تخمينية**: إن لم يحملهما المزوّد لا يُكتب شيء ولا يظهر شيء، وهذا السلوك المقصود. XSI يحمل حقل `attribution` لأن زينيتا تشترط الإسناد الصريح مقابل السماح للجميع باستخدام بياناته — **لا تحذف هذا الحقل**، فهو شرط الترخيص لا تزيين. الوصول المنظّم لبيانات XSI يُطلب من `xsi@xeneta.com`.
2. **أسعار خطوط من المساهمات** — الوحيدة التي نملكها ونستطيع نشرها بلا إذن أحد.

جدول الخطوط الـ٣٧ الموسوم «توضيحي» خرج من الصفحة الرئيسية وبقي في `/rates/` بلافتته، حتى تحلّ محله مساهمات حقيقية. لا تُعده إلى الواجهة قبل ذلك.

### مراقب المصادر — الصيانة بلا متابعة يدوية

`scripts/watch-sources.mjs` + `.github/workflows/watch-sources.yml`. يعمل **كل اثنين**، ويمكن تشغيله يدويًا من تبويب Actions.

ما يفعله: يعيد جلب كل مصدر يستشهد به الموقع، ويقارن ما نشرناه بما تقوله الصفحة اليوم. **لا يعدّل أي بيانات** — يفتح تذكرة (Issue) تصلك على بريدك من GitHub، وأنت تقرر.

- **قائمة المراقبة تُبنى من ملفات البيانات نفسها** (`freetime.json` و`advisories.json`)، فلا يوجد مكان ثانٍ تحدّثه: أضف مصدرًا إلى البيانات وهو يُراقَب تلقائيًا.
- **الصمت معلومة**: لا تُفتح تذكرة إن لم يتغير شيء. إن لم يصلك بريد، فالأرقام كما تركتها.
- ثلاث درجات في التذكرة: **رقم اختفى من صفحته** (إشارة قوية — حدّثه)، **صفحة تغيّر نصها وأرقامنا فيها** (نظرة سريعة)، **مصدر تعذّر الوصول إليه** (قد يكون انقطاعًا؛ إن تكرر أسبوعين فالرابط مات).
- يبحث عن **المبالغ (١٠٠ فأكثر) فقط**. الأعداد الصغيرة كـ«٣ أيام» شائعة في أي صفحة، فالبحث عنها يعطي نتائج كاذبة — لذلك تُكتشف بتغيّر نص الصفحة لا بالبحث المباشر.
- `.watch-state.json` في جذر المستودع يحفظ بصمة كل صفحة، وتكتبه المهمة بنفسها. لا تعدّله يدويًا، ولا تحذفه إلا إن أردت إعادة ضبط كل البصمات.
- للتجربة محليًا بلا فتح تذكرة: `node scripts/watch-sources.mjs --dry`.
- **بعد أي تحديث**: غيّر `verified` أو `asOf` في ملف البيانات حتى لو لم يتغير الرقم، ثم أغلق التذكرة.

- **نموذج جمع العروض** `/ar/contribute/` — يعمل عبر **Netlify Forms**. بعد أول نشر: في لوحة Netlify افتح **Forms** وتأكد أن اكتشاف النماذج مفعّل (Enable form detection) ثم أعد النشر مرة واحدة. تصل العروض في تبويب Forms، والخطة المجانية تستوعب ١٠٠ عرض شهريًا. فعّل الإشعار بالبريد من **Forms → Settings → Form notifications** حتى يصلك كل عرض فور وصوله.
  - المراجعة الأسبوعية: اجمع العروض على الخط الواحد، استبعد الأعلى والأدنى، خذ الوسيط، وحدّثه في `lanes` داخل `rates.json`.
- **معجم المصطلحات** `/ar/glossary/` و`/en/glossary/` — كل المحتوى في `src/_data/glossary.json`. لإضافة مصطلح انسخ أي عنصر واملأ `slug` و`term`/`def`/`note` بالعربية والإنجليزية و`cat` و`related`. تتولّد صفحته في اللغتين آليًا، ويدخل في البحث وخريطة الموقع. ثم شغّل `node scripts/og-images.mjs`.
- **خريطة الموقع** `/sitemap.xml` و**robots.txt** — تُولَّد آليًا، لا تحتاج صيانة.
- **خلاصات RSS** `/ar/feed.xml` و`/en/feed.xml`.
- **صور المشاركة**: بعد إضافة أي مقال جديد شغّل `node scripts/og-images.mjs` لتوليد صورته، ثم ادفع الصور مع المقال. يحتاج `rsvg-convert` وخط IBM Plex Sans Arabic مثبتًا محليًا (ليس مطلوبًا على Netlify لأن الصور تُرفع جاهزة).
- **التحليلات**: ضع رمز Cloudflare Web Analytics في `analyticsToken` داخل `site.json`. ما دام فارغًا لا يُحمَّل أي سكربت تتبّع.

## النشر (اختر واحدًا)

### Netlify (الأسهل)
1. ارفع المشروع إلى مستودع GitHub.
2. في Netlify: **Add new site → Import from Git** → اختر المستودع.
3. Build command: `npm run build` — Publish directory: `_site`.
4. اربط نطاقك من **Domain settings**. كل `git push` بعدها ينشر تلقائيًا.

### Cloudflare Pages
نفس الخطوات؛ Framework preset: Eleventy، Build output: `_site`.

### GitHub Pages
أضف ملف `.github/workflows/deploy.yml` يشغّل `npm ci && npm run build` ثم ينشر مجلد `_site` بإجراء `actions/deploy-pages`. (الموقع يعمل من مجلد فرعي أيضًا لأن كل الروابط نسبية.)

### أي استضافة أخرى
ارفع محتويات `_site/` إلى جذر الاستضافة عبر FTP أو لوحة التحكم. تأكد أن الخادم يخدم `index.html` للمجلدات (الافتراضي في كل الاستضافات تقريبًا).

## ملاحظات تقنية

- كل الروابط الداخلية نسبية (فلتر `rel` في `.eleventy.js`)، لذا يعمل الموقع من جذر النطاق أو من مجلد فرعي أو كمعاينة.
- `npm run build:preview` يُخرج نسخة في `_preview/` تنتهي روابطها بـ`index.html` لمنصات لا تدعم فهرسة المجلدات (هي النسخة المنشورة كمعاينة في Claude).
- الخط: IBM Plex Sans Arabic من Google Fonts. لاستضافة ذاتية للخط ضع الملفات في `src/fonts/` وعدّل `@font-face` في `style.css`.
- لا يوجد JavaScript سوى نموذج النشرة وزر نسخ الرابط؛ الموقع يعمل كاملًا بدون JS.
